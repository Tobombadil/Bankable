# services/social — syndication pipeline (Sprint 2)

Scope, per `.claude/agents/content-social.md` and the Sprint 2 task brief: the pipeline **up to
but not including actually posting to any network**. No social accounts exist yet — the owner
creates them per `docs/32-social-operating-playbook.md` §2. Everything here stops at a dry-run
preview of what would be sent.

## Modules

- **`models.py`** — `PostDraft` (pre-publish: draft/approved/rejected/scheduled/withdrawn) and
  `Post` (a frozen publish outcome, always `dry_run=True` in this package), plus `ReviewMetadata`
  and `ValidationResult`. Docs/21 §3.18 `post` entity, split into the two shapes the task brief
  asks for. JSON round-trippable (`to_dict`/`from_dict`) for `queue.py`'s store.
- **`editorial.py`** — `SocialEvent` (the structured-field contract of docs/32 §3.2), the docs/32
  §3.1 eligibility rules (`channels_for_event`), the per-channel templates of §3.3
  (`render_proposal_new`, ... `render_digest_weekly`), the §4.3 hard validation gates
  (`validate_draft`), attribution/disclosure/lag-notice builders, and `build_draft`/
  `draft_events` (the `event → draft` pipeline stage). Also the `from_diff_row` adapter from
  `pipeline/diff.py`'s prototype event shape (see "Known gap" below).
- **`queue.py`** — `ReviewQueue`, a JSON-file-backed review queue: `add_draft` (with docs/32 §4.8
  duplicate suppression: idempotency key, cross-event 7-day window with the withdrawn > status
  changed > new priority order, and a 30-day content-hash guard), `list_drafts`/`approve`/
  `reject`/`edit`, `expire_stale` (the §4.4 SLA clock), scheduling stubs (`schedule`,
  `next_available_slot`, `check_rate_limit` against the §4.7 "our ceiling" column), and
  `graduation_status` (the §4.6 auto-publish gate — always refuses; LinkedIn refuses
  unconditionally by decision).
- **`publishers/`** — `Publisher` (abstract) plus `BlueskyPublisher`, `LinkedInPublisher`,
  `XPublisher`. All three are dry-run only. Bluesky alone has a `feature_flag_live` switch for a
  future AT Protocol app-password flow; even with the flag on, it refuses without
  `BSKY_HANDLE`/`BSKY_APP_PASSWORD` in the environment and then raises `NotImplementedError` (no
  network call is wired — no account exists yet). LinkedIn and X have no live path at all in
  Sprint 2.
- **`__main__.py`** — the CLI: `draft`, `review list|approve|reject`, `dry-run`, `report`.

## CLI

```
python -m services.social draft --events <parquet> [--records <parquet>] [--queue-path PATH]
python -m services.social review list [--channel C] [--status S]
python -m services.social review approve <draft_id> --reviewer <email>
python -m services.social review reject <draft_id> --reviewer <email> --reason <code>
python -m services.social dry-run <bluesky|linkedin|x>
python -m services.social report
```

`draft` accepts two event-parquet shapes:

1. **The target contract** — one row per `editorial.SocialEvent` field (what a real `event` store
   built to docs/21 §3.10 will eventually emit).
2. **`pipeline/diff.py`'s prototype shape** — `event_type, record_id, source_id, field, before,
   after, observed_at`, one row per *changed field*. The CLI joins this against `--records` (the
   canonical snapshot from `pipeline/normalize.py`) and `data/sources.yaml` (read-only) to recover
   capacity/technology/place/provenance. `capacity_change`, `cod_change` and `removed` rows are
   dropped (never postable per docs/32 §3.1); `new`/`status_change`/`withdrawn` are mapped to
   `proposal.*` or, for opportunity-category sources, the closest analogue. A record-less `new`
   row (no `--records` match) has no size field and correctly never earns a post — thresholds are
   never guessed.

## Known gap: source id mismatch between `pipeline/diff.py`'s demo output and `data/sources.yaml`

`pipeline/diff.py --demo` (and `data/eval/events.parquet`, generated by it) writes short
connector-internal ids (`caiso`, `ercot`, `spp`, `nyiso`, `isone`, `eia860m`) into `source_id`,
while `data/sources.yaml`'s ids are the long canonical form (`us.iso.caiso.gen_queue`, ...). This
package's `_load_source_meta()` reads `sources.yaml` verbatim (read-only, per this task's write
scope) and cannot resolve those short ids, so running `draft` directly against
`data/eval/events.parquet` today yields zero drafts — not a bug in the eligibility logic, but a
naming seam between the Sprint 1 prototype and the source registry. Confirmed by re-running the
same join with a manual six-entry alias table (not shipped — a demonstration only):

```
170 diff.py events -> 170 SocialEvents (new/status_change/withdrawn only) -> 176 drafts
Counter({('bluesky','proposal.status_changed'): 36, ('x','proposal.status_changed'): 36,
         ('bluesky','proposal.withdrawn'): 20, ('x','proposal.withdrawn'): 20,
         ('bluesky','proposal.new'): 19, ('x','proposal.new'): 19,
         ('linkedin','proposal.new'): 13, ('linkedin','proposal.withdrawn'): 9,
         ('linkedin','proposal.status_changed'): 4})
```

Whoever builds the real `event` table (docs/21 §3.10) should emit the canonical `source_id`
directly, which removes the need for any alias table.

## Editorial decisions recorded as assumptions (not re-derivations of docs/32)

- **High-volume ISOs** for the "≥100 MW for solar/storage" bar (docs/32 §3.1): CAISO, ERCOT, SPP,
  MISO — the four largest queues per `docs/22` §1. Not named explicitly in `docs/32`.
- **Disclosure text** (`DISCLOSURE_TEXT`, task item 2): the docs/13 §6.5 "Automated social
  account" bio line for Bluesky and X; for LinkedIn (which never auto-publishes, docs/32 §1.4,
  §4.6), the human-review statement from the same table, since the Art. 50(4) exemption is what
  makes LinkedIn's manual-review policy sufficient. Carried as a `PostDraft.disclosure_text`
  field (audit metadata, matching docs/21 §3.18 `disclosure_label`) rather than appended inline
  to every body — the §3.3 templates verbatim have no disclosure clause; disclosure is an
  account-level bio/About statement in docs/32 §2.2, not a per-post one.
- **Attribution substring** (`attribution_line_for`): `"Source: {source_name}"` for every event
  type except `funding.cancelled`/`reinstated`, whose §3.3 template instead reads "... per
  {source_name} record dated ..."; the bare source name is what's common to both phrasings and is
  what the §4.3 gate 3 check ("contains the attribution line ... unchanged") is verified against.
- **`digest.weekly`** is exempt from the attribution-line and number-traceability gates (§4.3
  gates 3 and 5): it is a roll-up over `digest_items`, not a single-source, single-fact post, and
  its own §3.3 template has no `Source:` clause. Every other gate still applies.
- **Never-posted default-deny**: any `event_type` not in `POSTABLE_EVENT_TYPES` earns no post on
  any channel, including a `pipeline/diff.py` `removed` row (ambiguous — could mean withdrawn,
  cancelled, or a source hiccup — so it is never guessed into a post).
- **RFP/award/funding org and title fields are effectively required**, not omittable, once an
  event reaches that template: the fact line is meaningless without `issuer_org`/
  `solicitation_title`/`awardee_org`. `channels_for_event` already requires `awardee_org` for
  `opportunity.awarded`; the others are assumed present in every source-of-record RFP/award/grant
  entry.

## Tests

`tests/test_social_models.py`, `tests/test_social_editorial.py`, `tests/test_social_queue.py`,
`tests/test_social_publishers.py`, `tests/test_social_cli.py` — 138 tests. Coverage:

- Every entry in `POSTABLE_EVENT_TYPES` (a synthetic `SocialEvent` fixture per event type) earns a
  draft on at least one channel, fits its channel's character limit, and passes every §4.3 gate.
- Threshold edges (exact bar, high-volume-ISO bar, LinkedIn bar, load/voltage/capex alternates,
  "no size field at all never posts"), canonical-transition gating, RFP-closing's 14/3-day
  windows, awarded requiring a named awardee, restricted/unknown source denial, and the
  never-posted default-deny for made-up or field-level event types.
- Attribution and disclosure present on every draft; the lag notice present on proposal events and
  absent on live (opportunity/funding) ones; null fields omitted, never rendered as `"None"`;
  withdrawal reason quoted verbatim when present.
- Deterministic overflow handling: optional clauses drop before the mandatory fact/URL/attribution
  tail, and a body that still overflows after every optional clause is gone falls back to
  truncating the fact line — always fitting, always keeping `page_url` and attribution intact.
- Each hard gate's failure mode individually (banned words, unsolicited `@mention`, a stray URL, an
  invented number, a restricted `reuse_class`, missing disclosure).
- `idempotency_key`/`dedupe_key` stability and the withdrawn > status_changed > new priority order
  (`rfp_closing` always outranks).
- The `pipeline/diff.py` adapter: `capacity_change`/`cod_change`/`removed` rows dropped, a `new`
  row correctly joined to its canonical record, and a record-less `new` row never inventing a
  size to clear the threshold.
- The review queue: idempotency-key, cross-event-window (with priority override) and content-hash
  duplicate suppression; approve refuses on failed validation; reject requires a known reason
  code; edit stores a diff and re-validates; SLA expiry per channel; scheduling requires prior
  approval and respects the daily ceiling; **graduation always refuses** (LinkedIn unconditionally,
  everyone else on the 200-post/30-day/edit-rate/wrong_fact criteria); JSON persistence round-trips
  through a fresh `ReviewQueue` instance.
- Publishers: dry run never touches the network and reports the exact payload; Bluesky's
  `feature_flag_live` defaults off and even when on refuses without both credentials, then raises
  `NotImplementedError` rather than silently sending; LinkedIn and X always refuse a live call;
  the shared `validate()` gate catches a wrong-channel or unapproved draft.
- The CLI: `draft` end to end against a `diff.py`-shaped parquet (including the below-threshold
  record correctly earning nothing), idempotent on rerun; `review list/approve/reject`; `dry-run`
  previews without mutating draft state; `report` prints every docs/32 §6.2 section.

   (this pipeline drafts and queues; a human still presses send via each platform's own UI, a
   scheduler, or a future publisher's live path).

   event feed instead of a one-off parquet file.
6. Auto-publish (`docs/32` §4.6) is not a Sprint 2 decision: `queue.graduation_status` always
   returns `eligible=False` from an empty queue, and LinkedIn refuses it unconditionally by
   standing decision.
